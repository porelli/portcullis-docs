Manifest Reference¶

Every app template has a manifest.yaml that describes the app to the Hub. This page documents every field of the schema.

The authoritative definition is the JSON Schema (draft 2020-12) schema/manifest.schema.json in the templates repo. The Hub enforces the same rules and skips templates that fail them (see Integration Contracts §3). Rules that need the compose file, the filesystem or several templates at once are checked by tests/validate.py (see Validation).

For editor completion, start the manifest with:

# yaml-language-server: $schema=../schema/manifest.schema.json

Conventions¶

Several types recur throughout the schema:

Type Rule
single line A string without control characters (U+0000–U+001F, U+007F)
env key ^[A-Za-z_][A-Za-z0-9_]{0,127}$. It becomes a key in the per-app .env
group An LLDAP group name: ^[A-Za-z0-9][A-Za-z0-9_.-]{0,63}$
service A service name from the template's compose.yml: ^[a-zA-Z0-9][a-zA-Z0-9_.-]*$
{{DOMAIN}} In urls and redirect URIs, replaced with PORTCULLIS_DOMAIN (the main domain)
{{HOST_<ROUTER>}} NEW (contract v2). In urls and redirect URIs, replaced with the instance's full hostname for host router <router> (<ROUTER> as in instances)

No other keys are allowed. Every object in the schema sets additionalProperties: false, so a typo is an error, not a silently ignored field.

auth¶

Field Type Required Description
method enum Yes native-oidc, forward-auth, header-auth, mtls, custom or public (see below)
sso true, false or "partial" Yes Whether single sign-on is supported
group_access boolean Yes group-gate restricts the instance's hostnames to its access group (access_group for the default instance). For custom apps only while Portcullis sign-in is in front of them (native_login), or on a router-less custom template (no Traefik router), where the access group decides only who may create file-share passwords
group_admin boolean Yes The app maps admin_group to its admin role
access_group group If group_access: true LLDAP group required for access, by convention users_<app>. It is the default instance's group; every other instance uses users_<instance-id> (instances)
admin_group group If group_admin: true or admin_paths is non-empty LLDAP group for admin privileges, by convention admin_<app>. The default instance's; other instances use admin_<instance-id>
admin_paths list of path prefixes No Paths that additionally require admin_group (see below)
public_access object No Public path exceptions: share-link paths the Hub can open without forward-auth (see auth.public_access)
native_login object No The app has its own login and no SSO (method: custom only); enables the Hub's Sign-in setting (see auth.native_login)
keycloak_access_role boolean No native-oidc only, needs access_group. Keycloak itself refuses sign-in to anyone outside the instance's access group (see below)
identity_headers list of header names If method: header-auth and public_access is set Headers the app reads the user from (e.g. X-Forwarded-User); the Hub strips them on public paths
notes string No Free-text notes about the auth integration. Shown on the app's docs page, the portal (for an app without a web page), the policy view and the app detail. Upgrade constraints go here too

Constraints the schema enforces:

  • group_access: true requires access_group.
  • group_admin: true requires admin_group.
  • A non-empty admin_paths requires admin_group.
  • method: public requires group_access: false and an empty (or missing) admin_paths.
  • public_access is only allowed with method forward-auth, header-auth or native-oidc; with header-auth it requires a non-empty identity_headers (each ^[A-Za-z][A-Za-z0-9-]{0,63}$, unique).
  • native_login requires method: custom and sso: false.
  • Every method except custom needs at least one Traefik HTTP router. A custom template may have none (router-less: no web page), and may then set group_access: true without native_login.
  • keycloak_access_role: true requires method: native-oidc and access_group; so does method: native-oidc with group_access: false.

access_group is only enforced by group-gate when group_access: true. Otherwise it is informational, unless the Keycloak access role applies.

keycloak_access_role. The Hub restricts sign-in to the instance's access group in Keycloak (contract §8, "Access role"): every client of the instance gets a client role access, the access group gets that role, and the client's browser flow denies sign-in without it (also when the user already has a Keycloak session). The Hub does the same for every native-oidc template with group_access: false. Set it for apps that can't restrict sign-in to a group themselves or that let outsiders create accounts without rights (Immich, Headscale, NetBird, DokuWiki, Wiki.js, Actual), and as defence in depth on apps whose login paths are gated by group-gate or that check groups themselves (Paperless, Vaultwarden, GitLab, Nextcloud). It fails closed: without the group or the role nobody signs in. Only access-group members sign in — admin-group members too only if they are also in the access group. Every client of such an app has direct access grants, implicit flow, service accounts, device and CIBA grants and standard token exchange switched off (only the browser flow signs in): don't use it for an app whose client needs one of them. CI has no Hub, so the sign-in test runs without the access role (see tests.signin expected_fail).

Auth methods¶

method Meaning Router middlewares
native-oidc The app talks OIDC to Keycloak itself. Needs keycloak_clients No portcullis-auth on the host-wide router. Login or admin paths may use a separate PathPrefix router with forward-auth
forward-auth oauth2-proxy + group-gate in front. The app has its own login, or none portcullis-auth@docker,portcullis-groups@docker
header-auth Forward-auth, and the app also trusts X-Forwarded-User from Traefik (and only from Traefik) portcullis-auth@docker,portcullis-groups@docker
mtls A YubiKey certificate at the TLS layer (Traefik's protected option trusts only the YubiKey certificate authority: a browser certificate is refused at the handshake) tls.options: protected@file, no forward-auth
custom The app handles its own sign-in (app-specific account system, e.g. plex.tv). With native_login, the Hub can put Portcullis sign-in in front of it None: the Hub's override adds the gateway pair for Portcullis sign-in
public No authentication None

See Choosing an auth method in the templates repo's contributing guide.

SSO values¶

  • true: the user authenticates once in Keycloak and is logged into the app automatically.
  • false: the app has its own login form. Forward-auth only gates access, and the user logs in again.
  • "partial": the app auto-creates users from the identity, but needs extra setup, e.g. role assignment.

auth.native_login¶

For a custom app that has its own login and no SSO. The Hub then shows a per-app Sign-in setting and implements it with compose-override labels; the template itself never changes.

auth:
  method: custom
  sso: false
  group_access: true          # enforced only behind Portcullis sign-in
  access_group: users_plex
  group_admin: false
  native_login:
    supported: true
    allow_without_gateway: true
    note: Plex signs users in with plex.tv accounts; its TV and mobile apps need "App's own login only".
Field Type Required Description
supported true Yes The app's own login protects it on its own
allow_without_gateway boolean No (default false) Admins may choose App's own login only (no Portcullis)
note string (≤ 500) No Shown next to the Sign-in setting: what the app's login is, what breaks behind forward-auth

The two modes (Apps with their own login):

  • Portcullis sign-in, then the app's own login (default): every router gets portcullis-auth@docker,portcullis-groups@docker in front of its own middlewares, the TLS tier from the policy, and group-gate requires access_group if group_access: true. The access policy applies as for forward-auth.
  • App's own login only (only with allow_without_gateway: true): the template's middlewares without the gateway pair, public@file, no group.

Rules (schema and tests/validate.py; the Hub checks the first two too):

  • only with method: custom and sso: false: an app with SSO is signed in through Portcullis and never gets a way around it;
  • supported must be true (omit the block otherwise);
  • a custom app with group_access: true needs native_login (group-gate only runs behind Portcullis sign-in);
  • the compose file of a custom app never uses portcullis-auth@docker or portcullis-groups@docker: the Hub adds them.

admin_paths¶

admin_paths lists path prefixes on the app's hostnames that need the admin group in addition to the hostname's group. The Hub publishes them as group-gate path_groups (see Groups → Path rules).

Each item must:

  • match ^/[A-Za-z0-9._~%!$&'()*+,;=:@/-]*$, be at most 256 characters, and be unique in the list
  • not contain .. or //, and have no . segment (/./, a trailing /.)

Matching is a segment-boundary prefix match: /admin matches /admin and /admin/x, but not /administrator.

Path rules only take effect on routers that use portcullis-groups@docker. validate.py therefore fails if no router with portcullis-auth@docker,portcullis-groups@docker serves each listed path.

auth:
  method: native-oidc
  sso: true
  group_access: true
  group_admin: false
  access_group: users_vaultwarden
  admin_group: admin_vaultwarden
  admin_paths: ["/admin"]

auth.public_access¶

Public path exceptions let anonymous visitors use an app's share links (Nextcloud /s/<token>, Grafana shared dashboards) while the rest of the host stays behind Portcullis. The template only declares the paths. When an admin turns the exception on in the Hub, the Hub adds one Traefik router for them without forward-auth and group-gate (contracts §3). A template must never ship such a router in compose.yml. The app's own auth (share token, share password, expiry) is all that protects these paths; see Sign-in methods → Public exceptions.

Field Type Required Description
enabled_by_default boolean No (default false) State of the Hub toggle until an admin chooses
description string, one line, ≤ 500 No Shown in the Hub above the warning
default_mode listed or all No listed: only shares an admin lists in the Hub; all: every share. Default listed if a path has {token}, else all. listed needs a {token} path
token_pattern anchored regex ^...$, ≤ 200 If a path has {token} (and only then) Every listed share token must match it
credential_headers list of header names No Headers besides Authorization / Proxy-Authorization (always refused) the app logs a user in with, e.g. Immich x-api-key
credential_cookies list of cookie names No Cookies the app logs a user in with (session, remember-me, render keys)
credential_query list of parameter names No Query parameters the app logs a user in with (e.g. Immich apiKey, Grafana auth_token)
static_extensions list of [a-z0-9]{1,8} No Extra file extensions supporting paths may serve (default: avif css eot gif ico jpeg jpg js map mjs otf png svg ttf webp woff woff2). Script extensions (php, phtml, cgi, py, jsp, …) are refused
service compose service No Service the public router targets. Default: the only service with HTTP routers
paths list, 1–20 Yes See below

Each paths item:

Field Type Required Description
prefix path Yes Segment-boundary prefix: /s matches /s and /s/..., not /sx. Letters, digits and . _ ~ - per segment, optional trailing /; one whole segment may be {token}. Not / itself; no wildcards, .., //, %, ?, #, $, quotes or backticks
description string, one line, ≤ 200 Yes What the path is for (shown in the Hub and on the app page)
supporting boolean No Token-free path the share page needs. Opened in both modes, and only for static files below it unless exact. Can't have {token}
exact boolean No Opens only this path itself (Path, no subpaths): a single app route or file the page needs. Requires justification; can't have {token}. A path on the broad list (an exact /index.php is still the whole front controller) also needs broad: true
broad boolean No Acknowledges a prefix on the broad list; requires justification
justification string If broad: true or exact: true Why the broad prefix / exact route is needed

What each mode opens:

Path kind Mode listed Mode all
{token} path, e.g. /s/{token} /s/<t> for each listed token <t> /s (up to the segment before {token})
supporting: true static files under the prefix (see below) same
supporting: true + exact: true the exact path same
other token-free paths no segment-boundary prefix (or the exact path with exact: true)

Static files means Traefik's PathRegexp of the prefix, dot-free directory segments and a file name ending in a static extension, e.g. /dist/core-common.js or /core/img/actions/a.svg, but not /dist/, /dist/a, /dist/a.php or /dist/x.php/a.js. An app route that only accepts extension-less paths is therefore never reached through a supporting path.

Logins never ride the public router: core's public guard (contracts §5) answers 403 to requests carrying Authorization, Proxy-Authorization, a credential_headers header, a credential_cookies cookie or a credential_query parameter. Cookie and query names are compared case-insensitively after PHP's name mangling (leading spaces dropped, and . become _, name[…] is name), raw and percent-decoded. List every way the app authenticates a request at the pinned version.

In mode listed with no listed share, nothing is opened and no router is generated.

Rules (schema, tests/validate.py and the Hub):

  • Broad prefixes need broad: true and a justification: /api, /apps, /index.php, /ocs, /ocs/v1.php, /ocs/v2.php, /remote.php, /remote.php/dav, /remote.php/webdav, /public.php, /dav, /webdav, /graphql, /rest, /v1, /v2, /v3, /auth, /login, /user, /users, /account, /settings, /identity, /sso, /oidc, and any bare /<name>.php. A {token} path is checked on its mode-all extent (/api/{token} is broad).
  • Never public: anything overlapping /oauth2, /admin or /.well-known, or the app's admin_paths.
  • No overlap with other routers: a prefix (mode-all extent) may not overlap a Path/PathPrefix of another router on the app's hosts (login gates, admin routers, API splits). Traefik's PathPrefix is a plain string prefix, so PathPrefix(/login) overlaps /logins.
  • Analysable routing only: routers on the app's hosts may use only Host, Path, PathPrefix, Method, Header, HeaderRegexp, Query, QueryRegexp and ClientIP, without negation. PathRegexp, negated matchers or unknown matchers make the Hub refuse the template's public plan (it can't prove there is no overlap).
  • token_pattern must be anchored and compile, and must reject "", ., .., a/b, /, backticks, spaces, %2F, ${X}, ) and newlines. The Hub additionally requires tokens of [A-Za-z0-9._~-]{1,128}.
  • Routing names: routers and middlewares named portcullis-public-* are reserved for the Hub.

  • Service: with several routed services, set service. If it defines several Traefik services, exactly one host-wide router on it must name one.

  • Supporting prefixes are directories: a supporting prefix whose last segment looks like a file (/custom.css) must be exact.

Set enabled_by_default: true only when turning the exception on opens nothing by itself (mode listed) and can't weaken the host. Example (Nextcloud, abridged):

auth:
  method: forward-auth
  public_access:
    enabled_by_default: true
    default_mode: listed
    description: Public share links for people without a Portcullis account.
    token_pattern: '^[A-Za-z0-9-]{1,32}$'
    credential_cookies: [nc_username, nc_token, nc_session_id]
    paths:
      - prefix: "/s/{token}"          # quote: { } in flow style is YAML syntax
        description: Share page, password form, download and direct preview
      - prefix: "/public.php/dav/files/{token}"
        description: Public WebDAV of the share
      - prefix: /dist
        description: Compiled JS/CSS
        supporting: true                # static files only
      - prefix: /core/mimeicon
        description: File-type icon for files without a preview
        supporting: true
        exact: true
        justification: "#[PublicPage] route that only redirects to a static icon"
      - prefix: /apps/text/public
        description: Markdown viewer sessions (token in the body, so only in mode all)

settings¶

Options an admin (or each person) sets in the Hub: template contract v3, Integration Contracts §13. Each option has a type, a scope, constraints and one or more deliveries (how the value reaches the app). The Hub validates, stores, resolves and delivers the values; the template only declares them. Decoding is strict: an unknown key anywhere under settings, files, hooks or reload is refused.

settings:
  sections: [Storage, Accounts, Library]   # panel sections, in order
  options: [...]                           # the options below
Field Type Description
sections list of ^[A-Za-z0-9][A-Za-z0-9 ]{0,31}$, unique Panel sections, in display order
options list of options The options, in display order

A list directly under settings: (contract v2) is refused.

Immich example (abridged):

settings:
  sections: [Storage, Accounts, Library]
  options:
    - key: trash_days
      label: Keep deleted items for
      type: int
      unit: days
      min: 0
      max: 3650
      default: 30
      section: Library
      applies: restart
      delivery: [{env: IMMICH_TRASH_DAYS}]
    - key: storage_quota
      label: Storage quota
      type: size
      step: 1GiB
      allow_unlimited: true
      scope: person
      default: 100GiB
      resolve: max
      resolve_choices: [max, min, priority]
      section: Storage
      applies: next_sign_in
      delivery:
        - claim: {client: immich, name: immich_quota, json_type: int,
                  render: {unit: GiB, unlimited: "-1"}}
    - key: role
      label: Role
      type: enum
      options: [{value: user, label: User}, {value: admin, label: Administrator}]
      scope: person
      privileged: true
      default: user
      group_values: {"{{ADMIN_GROUP}}": admin}
      resolve: max
      section: Accounts
      applies: next_sign_in
      delivery: [{claim: {client: immich, name: immich_role, json_type: string}}]
    - key: external_library
      label: External photo library
      type: path
      mode: ro
      needs: read
      writes_as: {uid: 0, gid: 0}
      target: {service: immich-server, mount: /usr/src/app/external}
      applies: restart

description text, ≤ 500 chars, no control characters No Help text in the panel and on My apps
section one of settings.sections No Panel section
type see Types Yes

Types¶

Values are stored canonically: sizes in bytes, durations in seconds. Write sizes with binary units only (10GiB, 512MiB; 10GB and 10G are refused) and durations with a unit (30d, 90m, 60s). default, min / max / step and group_values must be valid values of the option.

Type Holds Constraints

Choosing runs_as and joins_group. Give the ids the app's process really has on the mount:

  • the image runs as root and the compose service sets no user: (Jellyfin, Immich): runs_as: {uid: 0, gid: 0} with the default group_add;
  • the service sets user: "1000:1000": the same numbers;
  • the service sets user: "${PUID:-1000}:${PGID:-1000}": runs_as: {uid_env: PUID, gid_env: PGID}, both instance int options;
  • the image drops supplementary groups before starting the app (s6 s6-setuidgid, su -g, many PUID/PGID images): a group_add gid never reaches the process. Use joins_group: gid_env so the Hub writes the folder's gid into the app's primary group variable instead (Plex: PLEX_GID), or, for a root process that keeps its own rights, say so in the notes (motionEye).

One primary group per process. With joins_group: gid_env every folder option of the service shares that one variable, so they must all use the same shared folder (subfolders are fine) or all use host paths; the Hub refuses an assignment that would need two gids ("point both settings at the same shared folder"). Plex's three libraries follow this rule; say it in the template's notes so admins know. The variable may not be read by another service's user: or group_add.

Hardware transcoding next to a folder block. Next to a folder block, every group_add entry of the target service must be a number or exactly one ${NAME} of an instance int option; group names (video, render) are refused. The render group's gid differs from host to host, so declare an int option (for example render_gid, env RENDER_GID, default 109) and write group_add: ["${RENDER_GID:-109}"]. A variable that isn't a declared int option is refused on every service.

Person-entered options¶

scope: person_entered: each person with access enters their own value (Firefox Sync's Mozilla account ID). See Adding an App for the full example.

  • Types string, int, bool or enum only (not secret). A string needs max_len (at most 256), a pattern or a format.
  • unique: true (string / int): no two people of one instance hold the same value. admin_override: true: admins may enter one for someone.
  • Refused: default, required, resolve, resolve_choices, group_values, privileged, requires (in either direction), self_visible: false, applies: account_creation.
  • applies must match the delivery:
    • file: the file's on_membership_change (restart → restart, reload → reload, hook → live; a file without one is refused);
    • hook: live, and the hook's when lists membership_change;
    • claim: next_sign_in; header: next_request;
    • env: restart, and render.join or render.format: json (the variable is the list of everyone's values).
  • A template whose routes can run without Portcullis identity (method public or custom, or native_login.allow_without_gateway) needs auth.access_group: its members may enter a value.

Per-person credentials and ids (person_secret, person_id)¶

Integration Contracts §13.16 and §13.17. Both types are allowed only on a router-less custom template (no Traefik router) with group_access: true and an access_group: its population is the access group's members. Setup options (setup, fixed_after_start, profiles)¶

NEW (apps). The Hub asks for an instance's setup choices before its first start (Install… / + Add instance), with their defaults (contracts §13.18). After the first start they are ordinary settings, except those with fixed_after_start: true: changing one would mean moving the data, so a save that changes it is refused (409); the way to another choice is a new instance and a restore of a backup.

A setup enum may switch which compose services run: profiles maps each value to the compose profiles it starts, and the Hub writes the instance's COMPOSE_PROFILES from the current values.

settings:
  options:
    - key: database
      label: Database
      type: enum
      options:
        - {value: mysql, label: MySQL / MariaDB}
        - {value: postgres, label: PostgreSQL}
      default: mysql
      setup: true
      fixed_after_start: true
      profiles:
        mysql: [db-mysql]
        postgres: [db-postgres]

# compose.yml
services:
  db-mysql:
    profiles: [db-mysql]
    # …
  db-postgres:
    profiles: [db-postgres]
    # …

Rules (the Hub and tests/validate.py refuse anything else, naming the option):

  • setup only on scope: instance options that aren't secret; fixed_after_start only with setup.
  • profiles only on setup enum options of scope instance, with a default; its keys are exactly the option's values (write value: [] for a value that starts no profile); each profile matches ^[A-Za-z0-9][A-Za-z0-9_.-]*$ and is listed by at least one compose service.
  • A compose service's profiles: is a list of literal names of that form, and every service with profiles: is started by some value of some option's profiles — otherwise the Hub would never start it.
  • A service without profiles: may not name a profiled service in depends_on, network_mode: service:<x> or volumes_from: compose couldn't start it for a choice that leaves that service off.
  • COMPOSE_PROFILES is the Hub's: a manifest may not declare it.

Each entry of delivery is exactly one of:

Delivery Form For

Headers are per-person values group-gate adds on the instance's hosts. NEW (VPN), optional. The template is a VPN (a mesh, a WireGuard server) that the admin may wire as a VPN provider for VPN-only access (contracts §3.3). The ingress namespace. ingress.service has no network_mode, isn't a job or a kind: companion AI service, and has no Traefik router or traefik.* label: the gateway is reached only over portcullis-vpn. tests.signin¶

How CI signs real users in to the app (tests/e2e/app_signin.py in the templates repo, run by test-apps.yml after the app's shell test). The Hub ignores tests. The test creates e2eadmin (access + admin group), e2emember (access group) and e2eoutsider (no group), registers the template's Keycloak clients and writes the group-gate policy as the Hub would, and signs each in through a setup link with a virtual security key. It passes when the member is signed in (and not admin), the admin has admin rights and the outsider is refused; a visible password field fails it unless password explains it. CI runs without the Hub: the clients are plain Keycloak clients, so the Hub's Keycloak access role (keycloak_access_role) is not applied there.

instances¶

NEW (contract v2). instances: multi lets the Hub run several fully separate instances of the template, each with its own project, volumes, settings, secrets, Keycloak clients, groups and hostnames (Integration Contracts §3.1 and §11). single (the default) means only the default instance, whose id is the template id. Keep a template single only when it needs host-level uniqueness (e.g. fixed host devices), and say why in auth.notes. Host ports are no reason: they are per-instance settings.

instances: multi

Hostname variables. Each hostname the template serves has one host router (a rule with Host() alone; path-scoped routers on the same host reuse its variable). The Hub sets PORTCULLIS_HOST_<ROUTER> to the instance's full hostname for it; <ROUTER> is the template's original router name upper-cased, with - and . turned into _. The default subdomain <sub> is one DNS label (^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?$), and a template uses one rule form for all its routers. Router rules use it with the default subdomain:

traefik.http.routers.grafana.rule: Host(`${PORTCULLIS_HOST_GRAFANA:-grafana.portcullis.local}`)
traefik.http.routers.vaultwarden-admin.rule: Host(`${PORTCULLIS_HOST_VAULTWARDEN:-passwords.portcullis.local}`) && PathPrefix(`/admin`)

Instance variables the Hub sets for every instance (never declare them in env, settings or ports; always use the default form with the default instance's value):

Variable Value
PORTCULLIS_INSTANCE Instance id (the template id for the default instance)
PORTCULLIS_HOST_<ROUTER> Full hostname for host router <router>
PORTCULLIS_OIDC_CLIENT_ID Keycloak client id of the first keycloak_clients entry
PORTCULLIS_OIDC_CLIENT_ID_<KEY> Keycloak client id of each entry; <KEY> = its client_id upper-cased, -/. → _ (two entries mapping to the same <KEY> are an error)
PORTCULLIS_ACCESS_GROUP The instance's access group (access_group for the default instance, else users_<id>)
PORTCULLIS_ADMIN_GROUP The instance's admin group (admin_group for the default instance, else admin_<id>)

A multi template has no ${PORTCULLIS_DOMAIN} in router rules (it may still use it for core hosts such as auth.${PORTCULLIS_DOMAIN:-portcullis.local}), no volume name: (the Hub sets portcullis_<key> for the default instance and portcullis_<instance-id>-<key> for the others), and no hard-coded Keycloak client id or group name in compose.yml. Routers that may serve extra-domain hostnames list portcullis-auth@docker on the router itself, never inside a chain middleware (the Hub swaps it for the extra-domain sign-in there, and refuses extra-domain hostnames for a router whose own chain reaches it).

hosts.immutable¶

Host routers whose hostname is fixed once the instance exists, for apps that bind their data to their own hostname (Synapse's server_name is part of every user and room id):

hosts:
  immutable: [matrix]   # host router names

The admin chooses the hostname when creating the instance; the Hub refuses every later change (409), the default instance's too, and moving it means a new instance. The default instance's immutable hosts start as <sub>.<main domain> and are pinned on its first enable: a later main-domain change never moves them (the instance shows as error until the old domain is added as an extra domain). A restore into a new id keeps the archive's hostname for such routers (contract §11.3, §11.6). tests/validate.py requires the list where it knows the app needs it (IMMUTABLE_HOSTS: matrix).

Validation¶

Run the validator from the templates repo:

python3 -m venv .venv && .venv/bin/pip install -r tests/requirements.txt
.venv/bin/python tests/validate.py            # all templates
.venv/bin/python tests/validate.py my-app     # one template (cross-template checks still run)
.venv/bin/python tests/validate.py --strict   # warnings fail too

It prints one line per problem with a hint. Exit codes: 0 OK, 1 rule violations, 2 usage or setup error. Besides the schema, it checks:

Layout

  • the directory name is a valid app ID (^[a-z0-9][a-z0-9_-]{0,63}$)
  • the files are named exactly manifest.yaml and compose.yml
  • tests/apps/<app-id>.sh exists
  • the directory is listed in .github/dependabot.yml
  • .core-ref holds exactly one ref

Manifest

  • no variable is written twice across env, ports and the settings' env deliveries, and none shadows a core variable
  • links (see links)
  • every secret_env is an env entry with generate: random
  • port bind values are IPs and range values are valid
  • config_files sources exist
  • auth.native_login only with method: custom and sso: false, and a custom app with group_access: true declares it

Networks and volumes

  • Traefik-routed services use networks: [default, portcullis-proxy], and internal services stay off portcullis-proxy
  • portcullis-proxy is declared external: true, and no other networks are used
  • volumes of single templates declare name: portcullis_<volume>, unique across templates and never external; volumes of multi templates declare no name: (NEW, contract v2)

Variables

  • core variables use their default form, e.g. ${PORTCULLIS_TRAEFIK_IP:-172.31.250.2}
  • instance variables (PORTCULLIS_INSTANCE, PORTCULLIS_HOST_*, PORTCULLIS_OIDC_CLIENT_ID*, PORTCULLIS_ACCESS_GROUP, PORTCULLIS_ADMIN_GROUP) use their default form with the default instance's value, the same default at every use, and are never declared in the manifest (NEW, contract v2)
  • every other variable is declared in the manifest
  • required ${VAR:?} variables are generate: random env entries

Services

  • no ports:, build:, container_name: or env_file:
  • every image is pinned tag@sha256:digest, and floating tags (latest, 16-alpine, ...) are rejected

Bind mounts

  • only ./templates/<app-id>/<file> (the file must exist) and ./certs/ca-bundle.crt:<path>:ro
  • never ./scripts/ or another template's files

Routers

  • every router has a rule of the form Host(`${PORTCULLIS_HOST_<ROUTER>:-<sub>.portcullis.local}`) (NEW, contract v2), optionally && <path matchers>, where <ROUTER> is the host router of that hostname; single templates may still use Host(`<sub>.${PORTCULLIS_DOMAIN:-portcullis.local}`). No core subdomain
  • each hostname has exactly one host router, no two host routers map to the same variable, and the template doesn't mix the two rule forms
  • no router, service or middleware name contains _ (NEW, contract v2)
  • entrypoints: websecure, and tls.options one of authaware@file, public@file, protected@file (mtls apps need protected@file)
  • security-headers@file is in the middlewares
  • portcullis-auth@docker and portcullis-groups@docker always appear together, in that order
  • forward-auth and header-auth routers use them; native-OIDC host-wide routers don't
  • public, custom and mtls routers use neither (for custom apps the Hub adds them, see auth.native_login)
  • each admin_paths entry is served by a gated router

Public exceptions (auth.public_access)

  • only for forward-auth, header-auth and native-oidc; header-auth apps list identity_headers, and every identity-like X-…/Remote-… header in compose.yml must be among them
  • the prefix, broad, never-public, overlap, matcher and token_pattern rules of auth.public_access
  • exact paths have a justification and no {token}; supporting prefixes don't name a file
  • no router or middleware named portcullis-public-*

Header trust

  • header-auth apps restrict identity headers to Traefik's IP
  • nothing trusts **, 0.0.0.0/0, ::/0 or the proxy subnet

Instances (NEW, contract v2; instances: multi)

  • no ${PORTCULLIS_DOMAIN} in any router rule
  • every env value, hostname: or label that names one of the template's own hosts uses its PORTCULLIS_HOST_<ROUTER> variable (no https://<sub>.${PORTCULLIS_DOMAIN…} for its own subdomains)
  • urls and redirect URIs name the template's own hosts only as {{HOST_<ROUTER>}}
  • no hard-coded Keycloak client id or group name in compose.yml (use PORTCULLIS_OIDC_CLIENT_ID*, PORTCULLIS_ACCESS_GROUP, PORTCULLIS_ADMIN_GROUP)
  • no router, service or middleware name starting with portcullis-, and no own paths under /oauth2/
  • bind mounts of support files are read-only (:ro)

AI support (check_ai, the Hub's ValidateAI rule for rule; NEW)

  • an ai: block with exactly one of mcp and unsupported (non-empty, ≤ 200 characters); alternative and chat only with unsupported, on_change only with mcp
  • the alias portcullis-mcp-<id>--<companion> is one DNS label: 15 + len(<id>) + 2 + len(<companion>) ≤ 63, checked with the template id (the default instance; the Hub also checks it for every other instance at create and at AI switch-on)
  • companions: the field rules of ai; source set; service in compose.yml with a name matching ^[a-z0-9]+(-[a-z0-9]+)*$; a companion service without Traefik labels, off portcullis-proxy, without network_mode / container_name / hostname, used by one companion; router a host router; public_path rules; builtin with upstream: official; app_oauth only builtin, with revoke and modes: [read_write]; app_token with mint and revoke; identity_headers with a caller_secret whose env is a generate: random entry; default_mode in modes
  • every hook the block names exists with exactly when: [ai]; no ai hook the block doesn't name; ai never next to another trigger
  • no ai.mcp with auth.admin_paths, auth.method public or mtls, or without an HTTP router
  • ai_client only in an ai.chat template, which has exactly one
  • the prefix portcullis-mcp- nowhere in compose.yml (any key or value, case-insensitive: router, service or middleware names, compose services, container_name, hostname, network aliases included); no keycloak_clients[].client_id starting portcullis-ai-; mcp isn't a default subdomain; the core names mcp-gate (service), mcp_gate_data (volume) and the Traefik names mcp, hub-mcp, people-mcp, mcp-gate are reserved
  • a companion service publishes no host ports; no service uses network_mode: service:<a companion service>; an identity_headers companion has its trust network (above)
  • PORTCULLIS_AI_* and PORTCULLIS_MCP_GATE_IP never declared; PORTCULLIS_AI_ENABLED / PORTCULLIS_AI_READONLY_<NAME> only as ${…:-false} / ${…:-true}, PORTCULLIS_MCP_GATE_IP only as ${PORTCULLIS_MCP_GATE_IP:-172.31.250.3}; PORTCULLIS_AI_PROVIDER_* never referenced, and no service sets one (an environment key or list item, any case); no environment variable name built by interpolation; no PORTCULLIS_AI_ in a ${…} default or alternate value; ai-providers not a files[] name
  • an ai_client entry has secret_env; ai.chat.file.mount doesn't collide with a files[] mount on that service; AI hooks don't run on a kind: companion service
  • companion images pinned tag@sha256:digest like every image

VPN (check_vpn, the Hub's ValidateVPN rule for rule, with the same refusal texts in the same order through the shared vectors tests/vpn_vectors.json; NEW)

  • the field rules of vpn: vpn.label: a single line of 1–64 characters, vpn.ranges: 1–8 IPv4 prefixes, vpn.ranges[<i>]: <v> is not an IPv4 prefix between /8 and /30, vpn.ranges: <a> overlaps <b>, vpn.ranges[<i>]: {{setting:<k>}} must name a cidr setting, vpn.ingress.proxy_protocol: only v2, vpn.identity.source: hook or static, vpn.identity.owner: oidc_sub or username, vpn.identity: source static takes no hook or owner, vpn.identity.refresh: between 15s and 10m, vpn.dns: exactly one of hook and manual: true
  • the ingress service and its namespace: vpn.ingress.service: <s> is not a service of compose.yml, … has network_mode, … is a job, … is an AI companion, … has a Traefik router, … publishes ports, … shares <s>'s network namespace: only the pinned ghcr.io/porelli/portcullis-forwarder image may; vpn: service <n> uses network_mode: host, vpn: service <n> uses pid: host
  • hooks: vpn.identity.hook / vpn.dns.hook: <h> is not a hook with exactly when: [vpn], hooks[<n>]: when: [vpn] needs a vpn: block that names it, hooks[<n>]: vpn can't be combined with other triggers
  • vpn.control_routers: <r> is not a host router of the template, vpn.control_routers: <r> serves an admin UI
  • every template router, with or without a vpn: block: router <r>: entrypoints must be 'websecure' (the Hub adds vpnsecure per instance)
  • reserved: ${PORTCULLIS_VPN_*} anywhere ($$PORTCULLIS_VPN_EDGE in a shell is fine) and as a settings/env key; the prefix portcullis-vpn anywhere in compose.yml; the core names wg (service), wg_data and vpn_doc (volumes), portcullis-vpn, portcullis-vpn-edge, portcullis-metrics-wg and wg-egress (networks). strip-client-forwarded@file may be listed in a router's middlewares (core runs it first anyway)

Cross-template

  • no default subdomain or volume name is used by two templates

Settings, files, hooks and reload¶

check_settings in tests/validate.py refuses what the Hub refuses when it discovers the template, with the same messages (setting <key>: …). A green Lint means the Hub lists the template. Besides the field rules above:

  • Options: keys unique; section listed in sections; label, description, scope and applies valid; the type known (contract v2 types and the reserved folder type refused); only the constraints the type takes; default, bounds, step and group_values valid values of the option.
  • Scope fields: privileged, self_visible, resolve, resolve_choices and group_values only with scope: person, which needs a default; admin_override only with person_entered; no default for group; unique only for lists and person-entered string / int; generate only for secrets; writes_as only for paths; paths instance only.
  • Privileged: enum or bool only, the default its lowest value, no {{ACCESS_GROUP}} preset.
  • resolve fits the type; group_values keys are only {{ACCESS_GROUP}} / {{ADMIN_GROUP}} and the manifest declares that group.
  • requires: instance options only, naming existing instance options, not itself.
  • Deliveries: each one exactly one kind; at least one for every scope but instance; a per-person delivery for person; no per-person env; group env with render.format: json; applies: live with a hook (or a file with on_membership_change: hook); applies: reload and on_membership_change: reload with reload.
  • Env: the name rules of Deliveries; compose interpolates it and doesn't hard-code it; indexed env only for instance lists with max_items (≤ 64), covering every index compose references.
  • Claims: native-oidc, a declared client, a name that isn't reserved, a json_type that fits the render, one option per claim and client.
  • Headers: the name form, gated routers, every router to the backend's network namespace behind forward-auth, no identity-less method, no Traefik-labelled network_mode: host service, one option per header.
  • Files: declared, field only for per-person scopes, one option per field; names unique, services in compose.yml, mounts absolute and clean, not colliding with another file or a path target on the same service.
  • Hooks: names unique, services in compose.yml, a non-empty argv without control characters, valid when, timeout ≤ 10m.
  • Reload: {service, signal} or {hook}, not both; the service or hook declared; signal HUP, USR1 or USR2.
  • Person-entered: the rules of Person-entered options.
  • Render: units, integer, unlimited (required with allow_unlimited), true / false, join and format fit the type; yaml / csv only on file and hook deliveries (never for a person_entered scalar); on an env delivery true, false, unlimited and join without ' or \; a numeric unlimited no size within min / max renders as.
  • Values: the default and every group_values value render through every delivery (the implicit UPPER(key) env included), and an env value holds no ', \ or line break (JSON text: no \" escapes either).
  • Secrets: scope: instance only; generate.length within min_len / max_len.

  • Shared folders, checks and gids: the rules and every refusal are listed in contracts §13.15. In short: folder only on instance path options and never with mode, needs or writes_as; runs_as matches the service's compose user:; gids 60000–60999 (the folder groups) are refused wherever a gid comes from; on every service, the compose user: uid is a whole number, a user name or one reference, its gid a whole number or one reference, and each group_add entry a whole number, a group name or one reference, where a reference is exactly $NAME, ${NAME}, ${NAME:-n} or ${NAME-n} naming an instance int option (no mixed text, nesting or + forms); YAML !!binary is refused anywhere.

  • Setup options and jobs (NEW (apps)): the rules of Setup options and jobs, with the Hub's messages (setting <key>: …, jobs: <service> …, service <s>: …).

  • File sharing (Per-person credentials and ids): person_secret / person_id only on a router-less custom template with group_access: true and access_group; their fields as listed (wrong hash, length < 24 or not a multiple of 4, a list or non-file delivery, a missing or colliding mount, revoke_on_leave not true, on_restore not void, no hook on mount.service with credential_change, any scope field, an unknown pool, self_visible not false on person_id, a bad username.pattern, an info placeholder naming an unknown or ineligible option or port are refused); uid_from / gid_from name a person_id option, gid_from needs uid_from and joins_group: template; requires_any names existing instance options, not itself; format: tsv files get no secret and no table; expand_members only on file deliveries of group / groups options; credential_change is a valid when; the volume key portcullis-hub-secrets is refused (as a key, a volume source and in volumes_from); ${PORTCULLIS_LOCAL_NETWORKS} only in exactly that form; ${PORTCULLIS_FOLDER_GID_<KEY>} only in exactly that form, in environment: of the service a folder option <KEY> targets.

The validator also warns when a service reads a secrets file but runs neither as root nor as user: "10001".

Complete example¶

A native-OIDC app with path settings, generated secrets and a Keycloak client:

# yaml-language-server: $schema=../schema/manifest.schema.json
name: Jellyfin
description: Free and open-source media server -- movies, TV, music, live TV
icon: "\U0001F4FA"
category: media
tags: [media, movies, tv, music, streaming, opensource]
links:
  website: https://jellyfin.org/
  source: https://github.com/jellyfin/jellyfin

auth:
  method: native-oidc
  sso: true
  group_access: true
  group_admin: true
  access_group: users_jellyfin
  admin_group: admin_jellyfin
  notes: >
    SSO-Auth plugin with group enforcement. Users must be in access_group
    to log in. Members of admin_group get Jellyfin admin.

settings:
  sections: [Libraries]
  options:
    - key: movies_path
      label: Movies folder
      description: Host path to your movies library
      section: Libraries
      type: path
      mode: ro
      needs: read
      writes_as: {uid: 0, gid: 0}
      target:
        service: jellyfin
        mount: /data/movies
      applies: restart

env:
  - key: JELLYFIN_ADMIN_PASSWORD
    description: Jellyfin admin password
    generate: random
  - key: JELLYFIN_OIDC_SECRET
    description: Jellyfin OIDC client secret
    generate: random

keycloak_clients:
  - client_id: jellyfin
    secret_env: JELLYFIN_OIDC_SECRET
    redirect_uris:
      - "https://media.{{DOMAIN}}/sso/OID/redirect/keycloak"
    name: Jellyfin

config_files: []

urls:
  - label: Jellyfin
    url: "https://media.{{DOMAIN}}"

ai:
  unsupported: "No official MCP server; community servers are small and not vetted by Portcullis"
