## Authentication

| Property | Value |
|----------|-------|
| **Method** | `native-oidc` |
| **SSO** | :white_check_mark: Yes |
| **Group Access** | :white_check_mark: |
| **Group Admin** | :x: |
| **Access Group** | `users_gitlab` |
| **Admin Group** | `admin_gitlab` |
| **Subdomain** | `git` |

!!! info "Auth Notes"
    Full OIDC with Keycloak. git-over-HTTPS, the API, the registry and CI runners are not behind forward-auth and work with personal access tokens. The sign-in, sign-up and OIDC paths (/users/...) are behind forward-auth + group-gate, so only members of users_gitlab can log in or have an account auto-created (GitLab CE has no OIDC group restriction; required_groups and admin_groups are Premium/Ultimate only). Existing GitLab sessions survive removal from the group until they expire; block the user in GitLab to cut access immediately. Admin rights are granted in GitLab (root account uses GITLAB_ROOT_PASSWORD); admin_gitlab is not mapped. Upgrades: the image is pinned; GitLab must be upgraded along its documented upgrade path (required stops between versions), never by jumping straight to the newest release.

## Routing

Traefik routers from `compose.yml`. The Hub replaces the TLS tier with the one derived from the app's [access policy](../operations/auth-policies.md#traefik-tls-tier).

| Router | Host | Paths | TLS tier | Forward-auth + group-gate |
|--------|------|-------|----------|---------------------------|
| `gitlab` | `git.<domain>` | all | `authaware@file` | :x: |
| `gitlab-login` | `git.<domain>` | `/users` | `authaware@file` | :white_check_mark: |
