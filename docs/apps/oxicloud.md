!!! info "Auth Notes"
    Native OpenID Connect (OxiCloud 0.10.0) and nothing else: OXICLOUD_AUTH_METHODS=oidc turns password login, sign-up and the OPAQUE endpoints off, and OIDC hard-disables magic links. The login page redirects straight to Portcullis. OxiCloud has no OIDC group restriction of its own, so the authorize endpoint (/api/auth/oidc/authorize, which mints the login state the callback requires) is behind Portcullis sign-in + group-gate (access_group), and the Hub's Keycloak access role restricts the client to access_group as well. Accounts are created on the first SSO login and keyed on the OIDC issuer + sub; the OxiCloud username is the LLDAP username (preferred_username, lowercased; OxiCloud appends a suffix if it is taken). SSO logins are never linked to existing accounts by email (OXICLOUD_OIDC_AUTO_LINK_EMAIL_MATCH=false); a login whose email matches another account is refused instead, so two LLDAP users with the same email can't both sign in. admin_oxicloud members become OxiCloud admins when their account is created (first login); OxiCloud does not re-evaluate the role later, so promote or demote existing users in its admin panel. Nobody is the instance owner (OxiCloud never derives ownership from an IdP); an operator can name one with `oxicloud user promote-to-owner <username>` in the container. The first-run setup endpoint (POST /api/setup, a password owner account for whoever calls it first) is closed by the oxicloud-init one-shot before OxiCloud starts (it marks the instance initialized), and the app is routed only while it reports itself initialized. Sessions: Keycloak calls OxiCloud's back-channel logout (/api/auth/oidc/backchannel-logout) whenever a Keycloak session ends; the Hub signs a user out of Keycloak when they leave the group, so their OxiCloud sessions (7 d rotating refresh tokens) are revoked then. What remains until it expires or is revoked in OxiCloud: an access token already issued (at most 1 h) and app passwords (WebDAV/CalDAV/CardDAV, no expiry); deactivate the user in OxiCloud to cut those. Device sign-in (RFC 8628, /api/auth/device) is approved by a signed-in user: a member can be tricked into approving a code an outsider started, which signs the outsider in as that member (approve only codes you started). Public share links (/api/s/{token}, the share page and its assets) are answered by OxiCloud without Portcullis sign-in by design: the host router has no forward-auth (native OIDC). On a host whose policy requires a client certificate they are refused at the TLS layer like everything else; this template declares no auth.public_access, so no exception can be opened for them there. WebDAV, CalDAV and CardDAV clients use app passwords (created by the signed-in user under Settings); the Nextcloud-compatible API for Nextcloud desktop/mobile apps is off (it would add another login flow). Upgrades: read the OxiCloud release notes; don't bump the PostgreSQL major.

## Routing

Traefik routers from `compose.yml`. The Hub replaces the TLS tier with the one derived from the app's [access policy](../operations/auth-policies.md#traefik-tls-tier).

| Router | Host | Paths | TLS tier | Forward-auth + group-gate |
|--------|------|-------|----------|---------------------------|
| `oxicloud` | `drive.<domain>` | all | `authaware@file` | :x: |
| `oxicloud-sso` | `drive.<domain>` | `/api/auth/oidc/authorize` | `authaware@file` | :white_check_mark: |

| Variable | Description | Generation |
|----------|-------------|------------|
| `OXICLOUD_DB_PASSWORD` | OxiCloud database password | `random` |
| `OXICLOUD_JWT_SECRET` | OxiCloud session token signing key | `random` |
| `OXICLOUD_OIDC_SECRET` | OxiCloud OIDC client secret | `random` |
