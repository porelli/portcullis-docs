## Authentication

| Property | Value |
|----------|-------|
| **Method** | `native-oidc` |
| **SSO** | :white_check_mark: Yes |
| **Group Access** | :white_check_mark: |
| **Group Admin** | :x: |
| **Access Group** | `users_vikunja` |
| **Subdomain** | `tasks` |

!!! info "Auth Notes"
    Native OIDC (Vikunja v2.7.1). The login page redirects straight to Portcullis: local accounts are off (auth.local.enabled false), so Vikunja registers no password login, sign-up, password reset or invite link route at all, and LDAP is off. Who may sign in: Vikunja has no OIDC group restriction of its own, so the Hub enforces users_vikunja in Keycloak (keycloak_access_role: the client's access role and browser flow; direct grants and the other non-browser grants are off on the client). Accounts are created on the first SSO login, keyed on the OIDC issuer + sub and named after preferred_username (the LLDAP username; Vikunja picks a random one if that name is taken); they are never linked to an existing account by email or username (emailfallback / usernamefallback false). Users need an email in LLDAP (Vikunja requires the claim; it is display/notification only). Every SSO user is a regular user: Vikunja's instance admin is a paid feature (admin panel license) set only with the CLI, so admin_vikunja is not used. Team sync: Vikunja reads teams only from a custom vikunja_groups claim (objects with name and oidcID), which the Hub's Keycloak clients don't send; teams are managed in Vikunja. CalDAV and the API take Vikunja's own CalDAV / API tokens (created by a signed-in user), never a password. Public project links are off unless "Link sharing" is turned on. Outgoing requests to URLs users enter (webhooks, imports, avatars) may not reach private addresses. Removing a user from the group blocks new sign-ins (and the Hub signs them out of Keycloak), not Vikunja sessions or API / CalDAV tokens already issued: refresh sessions end after 24 h without use (VIKUNJA_SERVICE_JWTTTL, upstream 72 h / 30 days), an active one keeps refreshing; disable the user in Vikunja to end it, effective within 10 min (`vikunja user change-status`). Mobile and desktop apps sign in through Vikunja's own OAuth flow in the browser, i.e. through Portcullis. Upgrades: database migrations run when Vikunja starts; don't bump the PostgreSQL major.

## Settings

Options an admin sets in the Hub's [settings panel](../operations/hub.md#app-settings) (person-entered ones: each person, on [My apps](../operations/hub.md#my-apps)). **Scope** and **Applies** are explained in the [Manifest Reference](../guides/manifest-reference.md#settings).

| Setting | Type | Scope | Applies | Description |
|---------|------|-------|---------|-------------|
| **Link sharing** | `bool` | instance | `restart` | Let users share a project through a public link (anyone with the link, optionally a password, gets the rights the link grants; no Portcullis sign-in). Default: `false`. |

## Environment Variables

Per-app variables in the generated `.env`; `random` ones are generated by the Hub on first enable:

| Variable | Description | Generation |
|----------|-------------|------------|
| `VIKUNJA_DB_PASSWORD` | Vikunja database password | `random` |
| `VIKUNJA_SECRET` | Vikunja service secret (signs session tokens) | `random` |
| `VIKUNJA_OIDC_SECRET` | Vikunja OIDC client secret | `random` |
