## Authentication

| Property | Value |
|----------|-------|
| **Method** | `forward-auth` |
| **SSO** | :x: No |
| **Group Access** | :white_check_mark: |
| **Group Admin** | :x: |
| **Access Group** | `users_motioneye` |
| **Admin Group** | `admin_motioneye` |
| **Subdomain** | `cameras` |

!!! info "Auth Notes"
    motionEye 0.44 (motioneye-project, maintained: 0.44.0 in June 2026) has no SSO; its own login has two local accounts, "admin" (full configuration) and "user" (view only), whose passwords are empty after a fresh install. Access is gated by forward-auth + group-gate on the whole host, and motionEye's login stays as a second step: motioneye-init sets each account with an empty password to a generated one before every start (MOTIONEYE_ADMIN_PASSWORD / MOTIONEYE_USER_PASSWORD in this instance's .env, Hub data env/<instance>.env; hashed by motionEye, argon2), so motionEye never runs with its well-known empty default, and the healthcheck fails while either is empty. Share the admin password with your camera administrators and the user password with viewers; a password changed in motionEye's settings is kept (clearing one sets the generated value again at the next start). motionEye doesn't read any identity header, so no LLDAP user name maps to these accounts. The admin account can do everything motionEye can, including commands run on motion events inside the container. The UI is on the instance's private network only; the gate in front of it (nginx, the only container on portcullis-proxy) answers Traefik's address alone, never forwards the Portcullis session (Authorization, access-token headers, forward-auth cookies), and is healthy (= routed) only while motionEye refuses an empty password for the admin and user account names. Cameras: network cameras by URL (RTSP, HTTP/MJPEG; added in motionEye, reached outbound from the container) and up to four local V4L2 cameras listed in the Local cameras setting (e.g. /dev/video0; only those are passed in, not privileged, so several instances can each use their own; a path that doesn't exist on the host stops the container from starting). Live view goes through motionEye's own UI; motion's direct streaming ports (8081+, "Video Streaming" in the camera settings) are not published, so direct stream URLs only work inside the instance. Storage: set "Storage folder" to a host path (e.g. /srv/cctv) to record there instead of the instance's media volume; keep an eye on its size (motionEye's own "Preserve" settings delete old media). Not available in a container: shutdown/reboot, and SMB share mounts.

## Settings

Options an admin sets in the Hub's [settings panel](../operations/hub.md#app-settings) (person-entered ones: each person, on [My apps](../operations/hub.md#my-apps)). **Scope** and **Applies** are explained in the [Manifest Reference](../guides/manifest-reference.md#settings).

| Setting | Type | Scope | Applies | Description |
|---------|------|-------|---------|-------------|
| **Storage folder** | `path` | instance | `restart` | Host folder for recordings and pictures (empty = the instance's own volume). Mounted at `/var/lib/motioneye` (rw). |
| **Time zone** | `string` | instance | `restart` | IANA time zone for timestamps and schedules, e.g. Europe/Rome (default UTC). |
| **Local cameras** | `list` of `string` | instance | `restart` | Device paths of local (USB/V4L2) cameras, e.g. /dev/video0 (up to 4; empty = none). |
