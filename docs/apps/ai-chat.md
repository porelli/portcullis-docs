| **Subdomain** | `ai` |

!!! info "Auth Notes"
    LibreChat 0.8.8 signs people in through Keycloak (OpenID only: no password login, no local sign-up, no password reset). Only members of users_ai-chat get in: the Hub's Keycloak access role refuses everyone else, and LibreChat itself requires the access group in the ID token's groups claim. Accounts are keyed on the token's sub; the name shown is the LLDAP username. Nobody is a LibreChat administrator (OpenID accounts are plain users), and the configuration comes only from the Hub. The AI side: one MCP server, "All my apps" (https://mcp.<domain>/mcp), reached with each person's own OAuth token of the instance's ai-chat-mcp client (scope mcp:all): each person connects once and consents in Keycloak; nobody can add other MCP servers. Nothing a person does makes the server fetch a URL they chose: agents have no actions (OpenAPI calls), web search, code interpreter, file search or OCR, and of LibreChat's built-in tools only the calculator is offered. Conversations can't be shared (no shared links, public or not), and a link can't submit a prompt by itself. Models: the providers selected on the instance's AI tab (Hub Settings → AI), each shown under its label. Everyone who can open the instance can use every provider selected for it, and what they send, and what their apps return, goes to that provider; give a group other providers with another ai-chat instance and its own access group. Kinds: OpenAI-compatible servers and LiteLLM, OpenAI, Anthropic (LibreChat's native Messages API client), Google (Gemini through Google's OpenAI-compatible API, https://generativelanguage.googleapis.com/v1beta/openai unless the provider sets its own base URL) and Azure OpenAI deployment groups. AWS Bedrock isn't offered: LibreChat takes Bedrock credentials only from its own fixed variables, never as a configuration reference. Keys are never written to a file: librechat.yaml holds ${VAR} references LibreChat expands from its environment. A provider with per-person keys asks each person for their own key (not possible for Azure OpenAI: the instance refuses to start). A provider whose key isn't set yet is left out until it is. Upgrades: LibreChat's api and config services share one image; MongoDB stays on 7.0 (MongoDB 8 refuses Linux kernels 6.19 to 7.0.13) and its majors and Meilisearch minors move by hand with LibreChat's own compose file (the search index is rebuilt from MongoDB).

## AI support

This template is an **AI page**: an MCP client people chat in, connected to "All my apps" as each person. Its models come from the model providers in Hub Settings → AI (see [The AI page](../operations/ai.md#the-ai-page)).

| Provider kind | Per instance |
|---------------|--------------|
| OpenAI-compatible (`openai_compatible`) | several |
| LiteLLM (`litellm`) | several |
| Azure OpenAI (`azure_openai`) | several |
| Anthropic (`anthropic`) | one |
| OpenAI (`openai`) | one |
| Google (`google`) | one |

Not an app the AI acts in: The AI page itself: it is an MCP client, not an app the AI drives.

Why this choice, and what to know: [AI support → AI Chat](../operations/ai.md#ai-ai-chat).

## Environment Variables

Per-app variables in the generated `.env`; `random` ones are generated by the Hub on first enable:

| Variable | Description | Generation |
|----------|-------------|------------|
| `AI_CHAT_OIDC_SECRET` | LibreChat sign-in client secret (Keycloak client ai-chat) | `random` |
| `AI_CHAT_MCP_SECRET` | Secret of the ai-chat-mcp client (all my apps) | `random` |
| `AI_CHAT_SESSION_SECRET` | LibreChat OpenID session secret | `random` |
| `AI_CHAT_JWT_SECRET` | LibreChat access token signing secret | `random` |
| `AI_CHAT_JWT_REFRESH_SECRET` | LibreChat refresh token signing secret | `random` |
| `AI_CHAT_CREDS_KEY` | First half of LibreChat's credentials encryption key | `random` |
| `AI_CHAT_CREDS_KEY_2` | Second half of LibreChat's credentials encryption key | `random` |
| `AI_CHAT_CREDS_IV` | LibreChat's credentials encryption IV | `random` |
| `AI_CHAT_MONGO_PASSWORD` | MongoDB password | `random` |
| `AI_CHAT_MEILI_MASTER_KEY` | Meilisearch master key | `random` |
