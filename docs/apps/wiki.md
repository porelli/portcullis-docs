!!! info "Auth Notes"
    Native OIDC through Wiki.js' generic OpenID Connect strategy (key "portcullis"), configured by the wiki-setup sidecar at every start (GraphQL API, as the break-glass local admin). One Portcullis login: users pick "Portcullis" on the login page. Identity: Wiki.js keys accounts on the OIDC subject (the Keycloak id of the LLDAP user, never the email; Wiki.js has no username-claim option). It requires an email claim and only uses it for the profile; it would link a login to a user an admin pre-created for this strategy with the same email, so never pre-create users for the Portcullis strategy (LLDAP emails are user-editable). Rights come only from groups: new accounts get no group, and at each login Wiki.js sets the user's membership of the Wiki.js groups users_wiki (editors, created once; adjust its rights in Wiki.js) and admin_wiki (manage:system, re-applied every start) from the groups claim. The Guests group has no permissions (re-applied before every boot by wiki-init), so nothing is readable anonymously. Wiki.js can't restrict OIDC logins by group, so /login (also /login/portcullis and its callback) and the setup wizard's /finalize sit behind forward-auth + group-gate (users_wiki); a realm user outside the groups who still got an account has no rights. Removing a user from the groups takes effect at their next login (Wiki.js sessions last up to 14 days). Break-glass: the local admin admin@wiki.invalid with WIKI_ADMIN_PASSWORD (set by the sidecar's setup wizard on a fresh install); its password login goes through the GraphQL API, rate-limited by Wiki.js (5 per minute). Existing installs whose admin has another email or password: the sidecar logs that Portcullis sign-in is not configured; create that local admin (or give an admin those credentials) and restart. Hostname: wiki-init writes the site URL from the instance's hostname before Wiki.js boots, so a hostname change only needs a restart.

## Routing

Traefik routers from `compose.yml`. The Hub replaces the TLS tier with the one derived from the app's [access policy](../operations/auth-policies.md#traefik-tls-tier).

| Router | Host | Paths | TLS tier | Forward-auth + group-gate |
|--------|------|-------|----------|---------------------------|
| `wiki` | `wiki.<domain>` | all | `authaware@file` | :x: |
| `wiki-login` | `wiki.<domain>` | `/login`, `/finalize (exact)` | `authaware@file` | :white_check_mark: |
