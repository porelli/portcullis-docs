!!! info "Auth Notes"
    Access gated by forward-auth + group-gate. CloudBeaver's reverseProxy auth provider logs users in from X-Forwarded-User (the immutable LLDAP username; the provider has no email header) and trusts team/role headers from any peer with no allowlist, so CloudBeaver is kept off portcullis-proxy behind a small nginx gate (cloudbeaver-gate) that rejects (403) X-Forwarded-User or X-Forwarded-Email from anything but Traefik (PORTCULLIS_TRAEFIK_IP) and strips the X-User/X-Team/X-Role/X-Role-TE/name and X-Forwarded-Email headers. Accounts created when the header carried the email are named after it; rename them to the LLDAP username in CloudBeaver's admin UI. Roles and connections are managed in CloudBeaver. The server is configured automatically at first start (CB_SERVER_* / CB_ADMIN_*), so nobody gets the initial-configuration wizard; its local administrator cbadmin-<CLOUDBEAVER_ADMIN_SUFFIX> (password CLOUDBEAVER_ADMIN_PASSWORD, both generated per instance) is break-glass only. reverseProxy logs a user in as the CloudBeaver account named like X-Forwarded-User, so the administrator's name is per instance and non-guessable, and cloudbeaver-gate refuses (403) any X-Forwarded-User starting with "cbadmin" (case-insensitive), so no LLDAP user can become the local administrator. Before every start, cloudbeaver-config (a one-shot, JSON-aware patch of workspace/.data/.cloudbeaver.runtime.conf) re-enables the reverseProxy provider with X-Forwarded-User, and CloudBeaver doesn't start if that fails. Anonymous access is off (fail closed); on the first start cloudbeaver-config seeds the runtime config before the automatic configuration runs, so users sign in by X-Forwarded-User from the start.

## Environment Variables

Per-app variables in the generated `.env`; `random` ones are generated by the Hub on first enable:

| Variable | Description | Generation |
|----------|-------------|------------|
| `CLOUDBEAVER_ADMIN_PASSWORD` | Password of CloudBeaver's local administrator cbadmin-<suffix> (break-glass; set by the automatic server configuration) | `random` |
| `CLOUDBEAVER_ADMIN_SUFFIX` | Generated suffix of the local administrator's name (cbadmin-<suffix>), so no LLDAP user can match it | `random` |
