🐝 Zigbee2MQTT¶

Zigbee to MQTT bridge with its web frontend and a bundled, password-protected Mosquitto broker

Tags: home-automation, zigbee, mqtt, iot, smart-home
Website: https://www.zigbee2mqtt.io/
Source: https://github.com/Koenkk/zigbee2mqtt

Auth Notes

Zigbee2MQTT 2.14 has no user system: its frontend's only protection is an optional shared auth_token. It runs without one here: forward-auth + group-gate on the whole host is the sign-in, and every member of the access group has full control (pairing, device settings, OTA, the network key in Settings). The frontend is on the instance's private network only; the gate in front of it (nginx, the only container on portcullis-proxy) answers Traefik's address alone, so no other container reaches it unauthenticated. Zigbee2MQTT's onboarding wizard and failure page never open (Z2M_ONBOARD_NO_SERVER): they would configure the instance for whoever reaches them first; the instance settings are applied at every start instead (they override edits made in the frontend's Settings for the same keys). Coordinator: set either "Serial device" (the host path of a USB coordinator, best a stable /dev/serial/by-id/... path; only that device is passed into the container, not privileged, so several instances can each drive their own coordinator; a path that doesn't exist on the host stops the container from starting) or "Network coordinator" (tcp://host:port of an Ethernet/Wi-Fi coordinator such as an SLZB-06 or a ser2net bridge, reached outbound, with its Adapter type); with neither, Zigbee2MQTT is not started and its log says what to set. No host networking is needed: mDNS discovery of network coordinators isn't available, give their address. MQTT: by default the bundled Mosquitto 2.1 on the instance's private network, anonymous clients refused, two accounts with generated passwords (zigbee2mqtt for the bridge, homeassistant for Home Assistant), ACL limited to zigbee2mqtt/# and homeassistant/# (the base topic is fixed to zigbee2mqtt). The homeassistant account has an allowlist only (Zigbee2MQTT matches bridge requests case-insensitively, so writes are never denylisted): discovery (read homeassistant/#, write homeassistant/status), device and group state, endpoint state, availability and device-trigger actions, the bridge's state, info (its configuration without the network key, MQTT password and frontend token), devices, groups and event topics (never bridge/logging, where Zigbee2MQTT logs every MQTT publish with its payload, the extension / converter JavaScript source, definitions or health), [/]/set|get commands and the permit_join request; never other bridge requests (extensions, converters, options, backup, restart, OTA updates, ...) nor bridge responses. So in Home Assistant the bridge's log level select and restart button and the firmware update entities (Zigbee2MQTT OTA update requests) are refused, and Home Assistant can't clear retained discovery messages (deleting a device in Home Assistant leaves its discovery config; remove the device in Zigbee2MQTT, which clears it). Use friendly names without "/" (availability and two-level names aren't covered), or your own broker via "MQTT server". External JavaScript (extensions and converters, arbitrary code) is off unless the instance setting turns it on. The gate never forwards the Portcullis session (Authorization, access-token headers, forward-auth cookies) to the frontend. Passwords are written hashed by mosquitto-init at every start; Zigbee2MQTT stores its own MQTT password in configuration.yaml in its data volume (upstream behaviour). Or set "MQTT server" (+ user and password) to use an existing broker, e.g. the one Home Assistant uses (the bundled broker then idles). Home Assistant: with "Home Assistant discovery" on, Zigbee2MQTT publishes discovery messages; in Home Assistant add the MQTT integration with the broker address host:, user homeassistant and the password Z2M_BROKER_HA_PASSWORD from this instance's .env (Hub data env/.env). The MQTT port (default 1883) is bound to 127.0.0.1 by default; set its bind address to the host's LAN address (or 0.0.0.0) for a Home Assistant on another machine or in a container, or clear the port to keep the broker private. It is plain MQTT without TLS, protected by the password: use it on a trusted network only. Each instance needs its own MQTT port (the Hub's port collision check). The frontend's "Open in Home Assistant" links and device pages link to this instance's hostname.

Settings¶

Options an admin sets in the Hub's settings panel (person-entered ones: each person, on My apps). Scope and Applies are explained in the Manifest Reference.

Setting Type Scope Applies Description
Serial device string instance restart Host path of a USB Zigbee coordinator, e.g. /dev/serial/by-id/usb-ITead_Sonoff_Zigbee_3.0_USB_Dongle_Plus_...-if00-port0 or /dev/ttyUSB0 (empty = none).
Network coordinator string instance restart tcp://<host>:<port> of a network (Ethernet/Wi-Fi) coordinator, e.g. tcp://192.168.1.50:6638; used instead of the serial device when set. Needs the Adapter type.
Adapter type enum instance restart Coordinator firmware type: ember (Silicon Labs EFR32, e.g. Sonoff ZBDongle-E, SLZB-06M), zstack (Texas Instruments CC2652/CC1352, e.g. Sonoff ZBDongle-P), deconz (ConBee/RaspBee), zigate, zboss, zoh; auto lets Zigbee2MQTT detect a USB adapter. Choices: auto, ember, zstack, deconz, zigate, zboss, zoh. Default: auto.
Home Assistant discovery bool instance restart Publish Home Assistant MQTT discovery messages (homeassistant/#). Default: true.
External extensions and converters bool instance restart Allow Zigbee2MQTT's external JavaScript (extensions and converters saved from the frontend or over MQTT): arbitrary code that runs in the Zigbee2MQTT container. Off by default. Default: false.
MQTT server string instance restart An existing broker instead of the bundled one, e.g. mqtt://192.168.1.10:1883 or mqtts://broker.lan:8883 (empty = the bundled Mosquitto).
MQTT user string instance restart User for the MQTT server above (ignored for the bundled broker).
MQTT password secret instance restart Password for the MQTT server above (ignored for the bundled broker).

Variable Description Generation
Z2M_BROKER_PASSWORD Bundled Mosquitto password of the zigbee2mqtt user (the bridge) random
Z2M_BROKER_HA_PASSWORD Bundled Mosquitto password of the homeassistant user (Home Assistant's MQTT integration) random
