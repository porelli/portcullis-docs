Auth Notes

Native OIDC through Nextcloud's official user_oidc app (pinned v8.11.0, installed and configured by setup.sh at every start; upgrade it there). Sign-in is one Portcullis login: the login page redirects to Keycloak. Accounts are created on the first SSO login and keyed on the LLDAP username (preferred_username, unique-uid off, so the Nextcloud user id is the username); soft auto-provisioning is off, so an SSO login is never attached to an existing local account and nothing is matched by email (the user-editable email only fills the profile). Sign-in is restricted to access_group in Keycloak (keycloak_access_role, contract §8 Access role): only users_nextcloud members can sign in, so a member of admin_nextcloud who is not also in users_nextcloud is denied — put Nextcloud's admins in both groups (user_oidc's group whitelist + login restriction stay as a second check); both groups are synced into Nextcloud at each login, and members of admin_nextcloud become Nextcloud admins within a minute (nextcloud-cron maps them into Nextcloud's "admin" group and removes SSO accounts that left it). No password login at all: Nextcloud can't switch its password form off server-side, so every local account (the nc-breakglass admin the image creates at install, the "admin" of installs made before this template version, accounts created in the Users page) is disabled at every start and within a minute by nextcloud-cron; the login form is hidden. Move a local account's files to its owner's SSO account with occ files:transfer-ownership. An LLDAP user whose name is a local account (e.g. "admin" on older installs) gets "User conflict" until that account is deleted (occ user:delete). Desktop/mobile clients use Login Flow v2 and get app passwords; WebDAV/OCS accept only app passwords or tokens (token_auth_enforced). Break-glass is occ on the server, e.g. docker compose -p portcullis- exec -u www-data nextcloud php occ group:adduser admin (or user_oidc:provider, config:system:set, user:info). Removing a user from the groups blocks new SSO logins and drops the groups at their next login, not sessions or app passwords already issued (occ user:disable for that); single logout is off because the Keycloak client has no post-logout redirect URI. Hostname: setup.sh re-applies trusted_domains, overwrite.cli.url, overwritehost and overwriteprotocol from the instance's hostname at every start, so a hostname change only needs a restart. Public exceptions: the host is not behind forward-auth, so every share link already works without Portcullis sign-in, listed or not (Nextcloud's share token, password, expiry and brute-force protection apply; it sees the client IP via TRUSTED_PROXIES = Traefik). The Hub exception only changes hosts whose policy requires a client certificate: there, the listed share links (mode all: every share) and the static files their page needs are served without one, and logins (Basic auth, remember-me cookies) are refused on those paths. The PDF viewer page (a PHP route) is not in the list, so on such hosts PDFs on a share download instead of opening inline; Markdown renders only in mode all. Apps installed under /custom_apps that hook the share page are not covered. Keycloak must be reachable at a public name and address: Nextcloud's HTTP client refuses hosts with a local TLD (.local, .lan, ...) or a private address (allow_local_remote_servers stays off; user_oidc has no switch scoped to the provider), so with split DNS or a LAN-only domain user_oidc answers "Could not reach the OpenID Connect provider". Never set user_oidc's httpclient.allowselfsigned (it turns TLS verification off). Upgrades: the image is pinned; Nextcloud only upgrades one major version at a time, so step through every major (e.g. 33 -> 34 -> 35) and never skip one. Keep nextcloud and nextcloud-cron on the same image. Settings: the default storage quota and the trash retention are applied live through occ by the apply-settings hook (apply-settings.php, run by the Hub as www-data in the nextcloud container at start and after every save; idempotent, exits non-zero on any occ failure). Quotas set per user in Nextcloud's Users page still win over the default. AI availability: while AI support is on, any container on portcullis-proxy can reach the companion and send wrong credentials; Nextcloud's brute-force protection counts them against the companion's address, which every AI request comes from, so such a container can slow everyone's AI requests down (sign-in itself still holds). Re-used usernames: accounts are keyed on the username, so a deleted person's username given to someone new gets the former person's Nextcloud account, on the web and through AI alike (the AI mint can't tell them apart: user_oidc stores no Keycloak id). Delete or rename the former person's Nextcloud account (occ user:delete) before re-using a username.

Public Exceptions¶

Public share links (/s/<token>) for visitors without a client certificate. Nextcloud's share password, expiry and download limits still apply.

The app signs users in itself (native OIDC), so these paths are reachable without Portcullis sign-in anyway. When an admin turns them on in the Hub, they are also served without a client certificate on hosts whose policy requires one (see Public exceptions).

Default: on, mode listed
Share token: ^[A-Za-z0-9-]{1,32}$
Refused by the public guard (login credentials): header Authorization, header Proxy-Authorization, cookie nc_username, cookie nc_token, cookie nc_session_id

Settings¶

Options an admin sets in the Hub's settings panel (person-entered ones: each person, on My apps). Scope and Applies are explained in the Manifest Reference.

Setting Type Scope Applies Description
Default storage quota size instance live Storage each Nextcloud account gets unless a quota is set for it in Nextcloud's Users page. Default: 10GiB.
Delete trash after duration instance live Deleted files are removed from the trash after this long (earlier only when an account runs out of space). Default: 30d.
